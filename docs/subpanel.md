# サブ液晶・タッチ・ボタン（PW-A9300）

2026-10-12〜13 に実機で確かめたこと。今は常駐プログラム `subpaneld` がサブ液晶をタッチパッドにし、右端の印刷のボタンと状態の帯を受け持つ（下の「subpaneld」）。MML の記号表はその先の構想。

## サブ液晶（キーボードの下）

- ST7586、240×120、4 階調グレー、SPI（ssp2 = `spi1.0`）。WinCE 側のドライバは `EDNA2_slcd_ST7586.dll`
- Linux 側は brain-hackers の DRM ドライバ `brain-st7586`（`drivers/gpu/drm/tiny/brain-st7586.c`）。`/dev/fb1`（`brain-st7586drm`、XRGB8888、1 行 960 バイト、1 画面 115200 バイト）
- **起動したままでは何も映らない。** Linux はサブ液晶の画面を一度も有効にしておらず、WinCE が最後に描いた画面（「スーパー大辞林3.0」など）が残っている
  - Xorg が `/dev/dri/card1` を GPU として追加し、systemd-logind 経由で DRM master を握る。このため fbdev からのモード設定・更新は `EBUSY` で断られる（`FBIOPAN_DISPLAY` も同じ）
  - 確かめ方: `sudo cat /sys/kernel/debug/dri/1/clients`（master が `y`）、`/sys/kernel/debug/dri/1/state` の `active=0`
  - 参考: PW-G5200 では書き込み + `FBIOPAN_DISPLAY` で映った（momoji-san「Brainのサブディスプレイ」 https://momoji-san.hateblo.jp/entry/2026/09/21/194153）。X が握っていなければその方法で足りるはず
- **映した方法（再起動なし）**: 文字のコンソールに切り替えて X に master を手放させ、そのあいだに fbdev でモード設定する。X に戻ってもサブ液晶は有効のまま

  ```sh
  sudo python3 userspace/subpanel/chvt.py 3      # chvt の代わり（kbd パッケージが入っていない）
  python3 userspace/subpanel/fbshow.py /dev/fb1 palette.raw   # FB_ACTIVATE_FORCE でモード設定してから書く
  sudo python3 userspace/subpanel/chvt.py 2      # X に戻る（X の VT は /sys/class/tty/tty0/active で確認）
  ```

  一度有効になれば、あとは `/dev/fb1` に書くだけで更新される（video グループなら sudo 不要）
- 今の形: `system/etc/udev/rules.d/72-brain-subpanel-seat.rules` で card1 を別の席（`ID_SEAT=seat-subpanel`、`master-of-seat` の印も外す）にする。Xorg は自分の席（seat0）の DRM 機器しか開かないので、起動の順番に関係なく card1 に触らない。subpaneld は fbdev（`/dev/fb1`）でモード設定して描く
  - 2026-10-13 に再起動して確認: Xorg.0.log に card1 が一度も出ず（開いたのは card0 だけ）、card1 の DRM のクライアントはなし、サブ液晶は `active=1`
  - それまでは `20-subpanel.conf` の `AutoAddGPU false` だけで、X は起動時の調べで card1 をやはり開いていた（`got fd for /dev/dri/card1`）。サブ液晶が映ったのは subpaneld（起動から 58 秒）が X（125 秒）より先にモード設定していたから。`AutoAddGPU false` は念のため残してある
- 階調: `brain-st7586` は XRGB8888 を gray8 にして上位 2 ビットで 4 階調にする。白 ff・薄いグレー aa・濃いグレー 55・黒 00。3 画素目のグレーが化けて 3 画素ごとに縦線が出る不具合があり、`kernel/0004` で直した（上流の st7586.c と同じ計算にした）
- 向き: `fb1` の左上がサブ液晶の左上（DTS の `rotation = <180>` で合っている）
- `userspace/subpanel/mkpalette.py` が記号表（8 列 × 3 段、1 マス 30×40 px）を作る。Chromebook 側で Pillow を使って作り、raw を送る（Brain には Pillow がない）

## ボタン

キーボードのマイコン（I2C0 の 0x28）が返す生のコード。`brain-kbd-i2c` を外して直接読んだ（`userspace/subpanel/inputlog.py`）。

| ボタン | コード | 今の割り当て（DTS の keymap） |
|---|---|---|
| 入/切 | 0x01 | `KEY_POWER`（Brainux の既定では logind が電源を切る。このリポジトリの設定では短く押すと眠る） |
| 音声 | 0x06 | `KEY_LEFTCTRL` |
| しおり | 0x25 | `KEY_F13`（`kernel/0007`。それまではドライバが黙って捨てていた） |
| Home | 0x24 | `KEY_F14`（同） |
| 辞書メニュー | 0x2b | `KEY_F15`（同） |
| 記号 | 0x0c | 記号面への切り替え（`symbol-keycode`） |

- キーボードのキーは取扱説明書 6 ページの図で 49 個、コードは 0x01〜0x31 の 49 個で一致する。keymap になかったのはしおり・Home・辞書メニューの 3 つだけ（0x0c の ∨/次見出 は記号面の切り替え）
- その 3 つは `kernel/0007` で F13〜F15 にした。X では XF86Tools・XF86Launch5・XF86Launch6。働きはユーザー空間で決める（再起動なしで変えられる）。今は Home（XF86Launch5）だけ、`system/home/user/.jwmrc`（Brain では `~/.jwmrc`。Brainux の `/etc/jwm/system.jwmrc` を Include して 1 行足す）で JWM のメニューを開く。しおり・辞書メニューは空けてある。JWM は `jwm -reload` では読み直さなかったので `jwm -restart`（ウィンドウは残る）。DTB の差し替えだけで済み、カーネルは作り直さなくてよい
- PW-A7200 の keymap の流用で、意味の合わないキーもある: 一括検索 = Esc、大辞林・英和大/和英・ブリタニカ・ビジネス = Tab・PageUp・PageDown・Insert、切替 = Delete、音声 = Ctrl、∧/前見出 = Alt、機能 = Shift
- 記号面で打てるのは数字と `` ` = \ ; ' [ ] , . / `` だけ。MML でよく使う `@ < > & ^ { } # +` などはない → サブ液晶の記号表で補う
- 外している間は `KEY_POWER` が logind に届かないので、入/切を押しても電源は切れない（実機で確認）

## subpaneld（`userspace/subpanel/subpaneld.py`）

Brain では `/usr/local/bin/subpaneld`、`subpaneld.service`（`-v` で詳しいログ）。root で動く。

- サブ液晶のタッチ（event0）を EVIOCGRAB で掴み、uinput の仮想マウス「Brain sub panel touchpad」を作る
- 表示の範囲はタッチパッド: なぞるとカーソルが相対で動く。タップ = 左クリック、長押し（0.6 秒）= 右クリック
  - タッチは 26 ms ごと（約 38 Hz）。押した最初のサンプルと離す直前のサンプルは跳ぶ（押したときは y に最大 6 px）。指を止めていても x は標準偏差 0.6 px、y は 1.2 px ぶれ、数 px ずつ這う（2026-10-19 に `touchrec.py` で記録して測った。subpaneld を止めて `sudo python3 touchrec.py 60 > touch.log`。最初に触れてから 60 秒）
  - 押した最初のサンプルは捨てる。カーソルは 1 サンプル遅れで、直近 3 サンプルの中央値（1 つだけの跳びと離す直前の跳びを除く）を追う。そのあと One Euro フィルタ（遅いときは強く、速いときは弱くならす）を通し、動いている間は 1 px 以内のぶれを出さない
  - 押した点から 3 px 動いたら動かし始める。動いた 3 px も捨てない（前は 4 px を捨て、6 サンプルに満たない払う動きではまったく動かなかった）
  - 加速: 指の速さ v（px/s。One Euro の速さ）に対して `1 + 2·v²/(v² + 250²)`。ゆっくり（50 px/s 前後）でほぼ 1 倍、ふつう（100〜170 前後）で 1.3〜1.6 倍、払う（1000 前後）で 3 倍近く。折れ目のない 1 本の曲線。縦はそれに 1.2 倍を掛ける（サブ液晶は縦が 120 px と狭いので。2026-10-20、本人の希望）
  - 離して 0.12 秒以内にまた触れたら同じなぞりの続きにする。なぞり始めにタッチが 27〜99 ms 切れることがあり、前はそれがタップ（左クリック）になっていた。そのためタップのクリックは離してから約 0.12 秒あとに出る
  - タップは 0.35 秒未満で、2 サンプル以上あり、全体が 20 px 以内に収まるもの（押したとき・離すときの跳びを含めて、タップは 7 px 以内だった。払う動きは 76 px 以上）
  - 生の値は横 12.8・縦 24.3 で 1 px（表示 240×120 px が生の約 3080×2920）。2026-10-19 まで縦にも横の 12.8 を使っていて、縦の動きを約 1.9 倍に数えていた
  - X の加速は切ってある（`20-subpanel.conf`）。前は evdev の classic（2 倍、threshold 4）が subpaneld の加速に重なり、最大 6 倍で、2 つの曲線が別の速さで効き始めていた
- 右端の印刷のボタン: 音量 大/小（ALSA の `Speaker`（0〜27）、イヤホンが挿さっているときは `Headphone`（0〜31）を、どちらも同じ 16 段の表で 1 段ずつ動かす。帯の棒は 1 段 3 ドット）、バックライト（メインを 7→5→3→1→7、サブはそれに合わせて 3/2/1/1）、クリア（Esc）
- 右端の幅 9 px の帯に状態を出す（各ボタンの横）: 音量の縦棒（背景は市松）とその下に出力のアイコン（右向きのスピーカーかヘッドホン、音量 0 なら灰色に斜線。イヤホンの抜き差しですぐ描き直す）、明るさ 4 段、電池 3 段（空は ×）と 5V のプラグ（右向き。ハブの抜き差しはキーボードのマイコンの知らせ（SW_DOCK）ですぐ描き直す。2026-10-17 までは 30 秒ごとの読み直しを待っていた）
  - 電池の段の決め方は [power-wince.md](power-wince.md) の「電池の見張りピン」に書いた（WinCE の解析とつながるので分けた）
  - 5V は `HW_POWER_STS` の VBUSVALID
- 30 秒ごとに状態を読み、触っていないあいだは select で眠る。描画は 1 回 6〜33 ms
- X がメイン液晶を消している間（DPMS。何も触らないと約 10 分）は、サブ液晶のバックライトも `bl_power` = 4 で消す（2026-10-20）。メイン液晶が消えているかは、DRM のコネクタの `/sys/class/drm/card0-DPI-1/dpms`（`On`/`Off`）で見る。メイン液晶のバックライトの `bl_power` も 4 になるが、蓋のとき（下）は subpaneld 自身がそこに書くので使わない。読むのは 30 秒ごとと、メイン液晶が消えている間にキーかタッチ（X を起こすもの）が来たら、そのあと 3 秒は 0.2 秒ごと。サブ液晶は、バックライトが消えても絵は残る
- `subpaneld.service` は `Nice=-10`（眠る準備で logind・NetworkManager・systemd が CPU を使う間も、下の円が止まらないように。タッチパッドの反応にも効く）

### 入/切と眠り（2026-10-16）

- 「入/切」（brain-kbd-i2c の `KEY_POWER`、掴まない）を押している間、帯の左に円を出し、logind の長押し（5 秒で電源オフ）に合わせて 5 秒で満たす（1 秒に 30 回描き直す）。満ちたら電源の印を黒くする（電源オフは logind がする）
- 5 秒より前に離すと、円は 4 倍の速さで巻き戻り、0 まで戻ったら月を出して、subpaneld が `busctl call org.freedesktop.login1 … Suspend b false` で眠りを頼む。短押しは logind に任せない（`brain-power-key.conf` の `HandlePowerKey=ignore`）。月より先に眠りが始まらないように、と、起きた直後の押下を logind が黙って捨てるため。起きてから 3〜4 秒は前の眠りの後始末中で、頼んでも断られるか、受け付けられて何も起きないので、眠りが始まった（下の pre の合図が来た）とわかるまで 6 秒ごとに頼み直す（15 秒まで）。それでも、起こして 1 秒で押すと眠らないことがある（本人の判断で、そんな使い方はしないので追わない）
- 眠りはどこから始まっても（蓋・`systemctl suspend`）、`system/usr/lib/systemd/system-sleep/brain-subpanel-sleep` が pre で SIGUSR1 を送り、subpaneld が月を描いて `/run/subpaneld-asleep` を作るのを 2 秒まで待つ（巻き戻しの途中なら、終えてから月）。月は画面の真ん中に 1 つだけで、音量・明るさ・電池の帯は消す（眠っている間に古い値を出さない。本人の希望）。サブ液晶は眠っている間もバックライトが消えるだけで絵が残るので、月が見えたままになる
- 起きたら、CLOCK_BOOTTIME と CLOCK_MONOTONIC の差が飛んだこと（0009 が眠った時間を BOOTTIME に足す）で気づき、眠る前の絵に戻して帯を描き直す（月の間は 0.2 秒ごとに見る）。post の SIGUSR2 でも戻る
- 起動のとき、円・月・電源の印の絵を先に描いておく（Python で数千の点を描くのは Brain では 1 秒近くかかり、押してから円が出るまで遅れた）。そのぶん subpaneld の起動に 5〜8 秒かかる
- 30 秒ごとの状態の読み直し（`amixer` を 2〜3 回起動して 1 秒近くかかる）は、円が動いている間はしない（円が 1 秒止まって飛んだ）
- サブ液晶を 1 秒に 30 回描き直すと、ときどき SPI が 10 秒止まって `brain-st7586 spi1.0: error -110 when sending command 0x2a` になった（3 分で 2 回）。上流の spi-mxs の修正の取り込み漏れで、`kernel/0011` で直した（4 分で 0 回）

### 蓋を閉じたまま鳴らすアプリ（2026-10-16）

自作の再生アプリ（SDL2）は、イヤホンで鳴らしている間は蓋を閉じても鳴らし続ける（本人と決めた）。そのために logind の handle-lid-switch の inhibitor が要るが、Brainux には polkit がなく、ふつうのユーザーには取らせてもらえない（`Access denied`）。polkitd を入れる案もあったが、常駐が一つ増えるのと、バックライトと電池の見張りも root が要るので、root で動く subpaneld が代わりに引き受けることにした（本人が選んだ）。

- `/run/subpaneld.sock`（Unix ソケット、mode 0666）。アプリは 1 行ずつ `keep-awake 1` / `keep-awake 0` を送る。つないでいるアプリのどれかが 1 なら、subpaneld が `systemd-inhibit --what=handle-lid-switch --mode=block … cat` を走らせて inhibitor を持つ。どれも 0 になるか、アプリが落ちて接続が切れたら、`cat` の stdin を閉じて外す。蓋が閉じていれば logind がそこで眠る
- 頼まれている間に蓋が閉じたら（キーボードの SW_LID。起動のときは EVIOCGSW で読む）、メイン液晶とサブ液晶のバックライトを `bl_power` = 4 で消し、開けたら 0 に戻す
- 電池の表示が空（×）になったら、つないでいるアプリに 1 度だけ `battery-empty` を送る（アプリは曲を止める）
- 確かめたこと（#18、2026-10-16、本人がイヤホンで）: 鳴らしたまま蓋を閉じると鳴り続け、両方のバックライトが消える。閉じたままイヤホンを抜くと、アプリが止めて頼みを外し、logind が眠る。電池が空の知らせはアプリに届いた（電池が切れかけたとき）
- 残っていること:
  - 空の知らせは 30 秒ごとの読み直しで 2 回続けて同じときだけなので、最長 1 分ほど遅れる。空の表示から Brain が止まるまでは約 2 分しかなかった（2026-10-16、5V があっても止まった。弱った電池）。止まったのは Chromebook から Wi-Fi で送っていたとき（瞬間的に電流が増えたのかもしれない）で、まれなことなので、空の表示で止めるままにする（本人、2026-10-16）
  - すでに空になってからつないだアプリには、知らせが届かない
  - 眠る前に止め終わるのを待たせる delay の inhibitor（`--what=sleep --mode=delay`）は頼めない。今はほかの delay（NetworkManager・system-sleep のフック）で間に合っている

### メイン液晶の枠のボタン

- メイン液晶のタッチ（SX8654）も掴む。表示の範囲（生の x 237〜3627。X の較正と同じ端）で始まったタッチは、uinput の「Brain main panel touchscreen」（0〜4095、INPUT_PROP_DIRECT）にそのまま流すので、X の較正（`99-calibrator.conf`）も今までどおり効く
  - SX8654 は 3.6 ms ごと（約 280 Hz）で、押している間は 1 サンプルに 1 px 以内と安定しているが、離す直前の最後の 1 サンプルが跳ぶ（11 回のうち 8 回、最大 100 px。2026-10-20 に `touchrec.py --main` でペンのタップ・なぞり・止めを記録した）。X はその位置で離したことにするので、ペンで押してもカーソルがとんでもないところへ飛んでいた。表示へのタッチは 2 サンプル（7 ms）遅らせて流し、離したときに残っている分は捨てる。2 サンプルに満たない短いタップは、押した位置で押して離す
  - タップでも、押してから離すまでにペンで 1〜6 px、指で 5〜15 px 動く。JWM は押した位置から 2 px 以内（`DoubleClickDelta`）で離したときだけルートメニュー（デスクトップの左クリック、`onroot="12"`）を開いたままにし、それより動くと離したときに閉じる（離した位置が項目の上ならそれを選ぶ）。メニューが出たり出なかったりしたのはこのため。押した点から 10 px（約 2 mm）動くまではカーソルを押した点に止めておき（タッチスロップ）、超えたらそのまま追う。ペンのタップは押した位置で離れるようになった。指のタップは 10 px を超えることがある
  - ドラッグ中は、X に渡す位置を 1 秒 60 回までにまとめる（`MAIN_INTERVAL`）。あわせて `~/.jwmrc` で、JWM の窓の移動・リサイズを枠だけで描き、座標を出さないようにした（`<MoveMode coordinates="off">outline</MoveMode>`、`ResizeMode` も同じ。Brainux の既定は opaque で、動くたびに窓の中身を描き直す）。そのうえで窓をドラッグしている間の CPU は、subpaneld 28%、SX8654 の割り込みのスレッド 15%、Xorg 6.5%、JWM 2%、空き 32%（2026-10-20、top を 15 秒）。subpaneld が読むまでの遅れは中央値 1 ms で、入力の側は間に合っている
  - それでも窓の移動・リサイズは重く、遅れてついてくる。大きな原因は画面の書き換えが 1 秒 20 回までだったこと（X の fbdev ドライバ → カーネルの fbdev の模倣は、deferred I/O で 50 ms ごとにまとめてパネルへ送る）。X を `modesetting` ドライバ（`system/etc/X11/xorg.conf`、kernel/0016 が要る）に替えると、変わったところをすぐ送るようになり、カーソル（サブ液晶のタッチパッド）は目に見えて滑らかになった。窓の移動・リサイズの重さはあまり変わらなかった（本人。2026-10-20）。1 画面を送るのは約 12 ms（LCDIF 25 MHz、1 画素 2 クロック。DMA なので CPU は使わない）。サブ液晶のタッチパッドで 20 秒動かし続けた間は Xorg 18%、カーソルの下のターミナル（lxterminal）21%、subpaneld 14%、空き 35%（fbdev のときの同じ測り方の値はない）。pmd-edit も問題なく動いた。`modesetting` は起動のときに画面のバッファ（300 KB の連続したメモリ）を自分で作らせるので、それが取れずに X が止まったことが 1 回あった（CMA を取っておく `kernel/0019` で手当てした。[stability.md](stability.md) の 7）
  - 較正（`99-calibrator.conf`）は合っていた（デスクトップの四隅をタップして、上の端 y 10〜12、下の端 y 283〜287 px、左右 9〜12・466〜470 px）
- 枠のボタンで始まったタッチは X に渡さず、押している間の y の中央値（前後 2 サンプルを除く）でボタンを決める。境目は上の表。働きは `MAIN_KEYS` に書く。2026-10-13 時点で、左の列は前見出 = Home、↑ = PageUp、↓ = PageDown、次見出 = End（本人が決めた）。右の列はアプリしだいで決めるので空けてある（ログに名前を出すだけ）
- 11 個とも、上から順に 1 回ずつ押して正しく判定された（生の記録は `~/brain-audio/logs/mainbuttons-2026-10-13.log`）。左の 4 つは `less` で効くこと、表示の端ぎりぎりのタップはカーソルとして効くことも確かめた
- 境目をはじめ表示の少し外（210・3700）にしていたら、端とのあいだで始まったタッチが X に渡ってカーソルが動いた。今は表示の端そのもの
- subpaneld が落ちると掴みが外れ、X は元の SX8654 から直接受け取る（ボタンは前のように画面の外を指す）

### タッチが固まる（LRADC の割り込みフラグの取り合い、`kernel/0005`・`0006` で直した）

- 症状: サブ液晶のタッチが「押されたまま」になり、以後イベントが来ない。`LRADC_CTRL1` が検出待ち（0x1000000）に戻らない
- 原因: タッチ（mxs-lradc-ts、ch6/7）と ADC（mxs-lradc-adc、電源の電圧を読む）が `LRADC_CTRL1` の割り込みフラグを共有している。ADC の割り込み処理がフラグを全部（0x1fff）消すので、タッチの変換の割り込みが消えて状態機械が止まる。brain-watch.sh が 10 秒ごとに ADC を読むので、触っているとそのうち当たる。逆にタッチ側も ADC の ch0 のフラグを消していた
- 直し方: ADC は自分のチャンネル（ch0、バッファ時は buffer_vchans）だけ、タッチは TOUCH_DETECT だけを消す
- 確かめたこと: ADC を 180 秒読み続けて 6164 回・エラー 0、そのあいだもタッチはすべて離された
- 固まったときの戻し方（修正前）: triggerhappy（thd）も event0 を開いているので、subpaneld を再起動してもデバイスは閉じられない。`systemctl stop triggerhappy` → subpaneld を stop・start → triggerhappy を start で、検出待ちに戻る。DELAY3 の KICK や CTRL0 の SCHEDULE を外から書いても戻らなかった
- 498 秒「押されたまま」のサンプルが流れ続けたことが 1 回あった（2026-10-13 未明、修正後）。固まったのではなくパネルが押されたと報告し続けていた。電池がほぼ空の時期で、原因は未確認
