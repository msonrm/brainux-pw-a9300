# 電源: WinCE の解析とつながる部分

> [!WARNING]
> **Brainux や linux-brain に電源まわりのコードを書こうとしている方は、この文書を読まないでください。**
> ここに書いたことには、シャープの WinCE を逆アセンブルして先に知っていたことが含まれます。読んでから書いたコードは、クリーンに書いたと説明できなくなります（[README](../README.md) の注意）。WinCE の解析を使っていない電源の記録は [power.md](power.md) にあります。

## WinCE の解析との関係

電源まわりでも、シャープの WinCE を逆アセンブルした（電池のドライバ `battdrvr.dll`、電源のドライバ `pmuPdk.dll`、本体の `nk.exe`。2026-10-12〜15）。解析の記録は公開していない。解析とコードを書くことは、同じ環境で coding agent（Claude Code）と進めた。分けて行う手順（クリーンルーム）は踏んでいない。

| 公開しているもの | WinCE の解析で先に知っていたこと | ほかの出どころ |
|---|---|---|
| 電池の見張りピン（`battpins.c`、`subpaneld` の電池の段、`brain-power.sh`、`vbuswatch.py`） | 見張りに使うピンが GPIO4_4・4_6・4_7・4_8 であることと、どのピンが 0 なら何段とみなすか（`battdrvr.dll`） | 実機（電池を替えて確かめた。使い切るまでの落ち方も記録した）、Scrapbox「PW-A9300」（あとで知った） |
| 電池の電圧（`battvolt.c`） | GPIO3_2 を 1 にして LRADC ch1 を半分にして読むこと（`battdrvr.dll`） | Scrapbox「PW-A9300」（電池の電圧だということ）、実機 |
| 5V の電流の上限と 4P2 の立ち上げ直し（`brain-5v-ilimit.c`、`ramp4p2.c`） | WinCE が 5V を挿したときに 4P2 を立ち上げ直し、上限を 480 mA まで段々に上げること（`pmuPdk.dll`・`nk.exe`） | 実機で読んだ WinCE が残した値、Freescale の BSP（GPL）、i.MX28 のリファレンスマニュアル |
| `deep` の眠り方（`kernel/0009`） | WinCE の眠り方（`nk.exe`、0009 を書いたのと同じ日に読んだ） | Freescale の BSP・Digi の版（GPL）、i.MX28 のリファレンスマニュアル |

どれも「ほかの出どころ」の列でも裏づけが取れる。ただ、同じ環境で解析していたので、解析から切り離して作ったとは言えない。キーボードのマイコンに電源を切ることを知らせる書き込み（`nk.exe` で読んだ）は、一度試して外した。公開しているものには入っていない。

brain-hackers は 2026-10 に、DLL の逆アセンブルを根拠にしたコードはクリーンルームの手順が要る、という方針を示した（[audio-ymu818.md](audio-ymu818.md) の「Brainux の方針との関係」）。上の 4 つは Brainux に提案しない。

## 5V から取る電流（4P2 の上限）

- 5V があるときの電源の経路: `HW_POWER_DCDC4P2` = 0x00c00000（ENABLE_4P2 と ENABLE_DCDC）、`HW_POWER_5VCTRL` = 0x24008113。5V から DCDC に給電できる設定だが、電池からどれだけ取っているかは未確認。ハブをつないだまま一日作業したあと、電池はほぼ空になっていた
  - 読み解き（i.MX28 リファレンスマニュアル 11.12.2・11.12.9、AN4199）: DCDC4P2 の DROPOUT_CTRL = 0（DC-DC の入力は 4P2）、CMPTRIP = 0（4P2 が BATT の 85% 以上なら 4P2 を使う）。つまり **i.MX28 の DC-DC はもう 5V（4P2 経由）で動いている**。ただし 5VCTRL の CHARGE_4P2_ILIMIT = 0x08 で、5V から取れるのは **100 mA まで**。それを超える分は 4P2 が下がって電池から取る。U-Boot の SPL は 0x3f（780 mA）まで上げる
  - **電池を抜いても USB だけで動く**（2026-10-13、上限 480 mA、ハブをつないだまま 30 秒ほど抜いて戻した）。液晶・Wi-Fi・SSH とも止まらず、BATT 端子も 3.5 V のまま。見張りピンは 1111 → 0011 → 0001 → 0000 と数秒おきに下がり、戻すと 1111。基板の電源も 5V から取れる。生の記録は `~/brain-audio/logs/battpull-2026-10-13.log`
  - 起動のしかたで値が変わる（WinCE が起動してからハブの 5V を挿した 2026-10-13 昼の 2 回目は 0x24027113 = 480 mA）。2026-10-13 昼に、電池を入れたまま USB 給電で起動したときは `5VCTRL` = 0x24027111（上限 0x27 = 480 mA）、`DCDC4P2` = 0x10c01600（DROPOUT_CTRL = 1: 4P2 を使い、4P2 が BATT より低いときだけ電池も使う）。Linux はこれらを触らないので、WinCE が最後に書いた値のまま
  - STS の DCDC_4P2_BO・VDDD_BO などは常に 1 で、使えない。`MINPWR` = 0x00001040 の PWD_BO で、電圧低下を見る回路が止まっている
  - `userspace/power/pwrpath.py`: 電源レジスタを読んで、DC-DC の入力・5V の電流上限・STS のビットが立つ割合を出す（root、読むだけ）。`--load` で CPU に負荷をかけながら測る
  - 2026-10-13 夕方、ハブをつないだまま `systemctl reboot` したときは 0x20（400 mA）だった。起動前から 5V があるときの値は一定ではないらしい
  - **`brain-5v-ilimit`（サービス）が起動時に上限を 480 mA（0x27）に上げる。** 下げることはしない。2026-10-17 から常駐し、5V が挿さったら 4P2 を起こし直す（下の「動いている最中にハブ（5V）を抜き差しすると」）。上の再起動で `0x24020111 -> 0x24027111` と上げたのを確認。`/dev/mem` に 32 ビット 1 回で書く（C。Python の mmap への書き込みは 1 回の 32 ビットになる保証がない）
  - **動いている最中に上限を下げない。** 試験のために 480 → 100 mA に下げたら、弱った電池では足りず 5 秒以内に止まった（2026-10-13。新しい電池に替えるまで起動しなかった）
  - 2 回目（2026-10-13）: ハブをつないだまま（`src=5v`）でも、見張りピンが 1111 → 0011 → 0001 → 0000 と下がり、0000 になって 17 分後に止まった（メイン液晶は真っ白、入/切も効かない。カーネルのメッセージは何も残っていない）。リセットで起こすと WinCE は 1 段・× なし、Linux は 0111。アルカリ電池は休ませると少し戻る。**上限 100 mA のままでは、ハブの 5V があっても電池は減る**（このときの上限は記録していないが、ゆうべの起動も 100 mA だったと見ている）。480 mA にしてからは、ハブの 5V で 70 分（2026-10-13 18:22〜19:33）使って見張りピンは 1111 のままだった。直前の眠りから起きたときは同じ電池で 0111 と 1111 の境目だったので、少なくとも減りは小さい
  - 3 回目（2026-10-15、上限 480 mA）: ハブをつないだまま、自作の再生アプリで曲を鳴らしたり SSH で読んだりしている間に、0011 → 0001（21:28）→ 0000（21:42 から揺れ、21:51 から 0000 のまま）と下がり、22:02 過ぎに止まった（journal の最後は 22:02:32。電池に ×、画面がちらついて真っ白、のちに暗くなる。サブ液晶のバックライトは点いたまま）。**480 mA でも、使っていればハブの 5V があっても電池は減る**。取り出した電池はかなり熱くなっていた（本人）。替えたあとの起動でレジスタを読むと、CHARGE = 0x10000（PWD_BATTCHRG = 1、BATTCHRG_I = 0。i.MX28 の充電器は止まっていて、電池に流し込んではいない）、THERMAL = 0x80（温度センサーは電源が切れている。STS の THERMAL_WARNING も 0）。i.MX28 の温度で落ちる仕組みは働いていないので、止まったのは電池が尽きたためと見ている。電池が熱くなるのは、空に近いアルカリ電池から電流を取り続けたため（電圧が下がると同じ電力に要る電流が増え、内部抵抗も大きくなる）と考えている。メイン液晶やバックライトなど、i.MX28 の電源の外にあって電池から直接取る部分があるのかもしれない（確かめていない）。**見張りピンが 0000 になったら、早めに電池を替える**（空のアルカリ電池を入れたままにしない）

## 電池の見張りピン

- **電池の残量は GPIO4_4・GPIO4_6・GPIO4_7・GPIO4_8 でわかる。** どれも GPIO の入力で、電池が減ると 0 になる。ほぼ空のアルカリ電池で 4 本とも 0、新しいアルカリ電池に替えると 4 本とも 1 になった（2026-10-12、5V はつないだまま）。電圧の数値は取れず、段階だけ。どのピンがどの順で落ちるかは、電池を使い切りながら記録して確かめる
  - この 4 本は、WinCE の電池のドライバ（`battdrvr.dll`）を逆アセンブルして見つけ、同じ日に実機で確かめた（電池を替えると 0 から 1 になった）。あとで、brain-hackers の Scrapbox の「[PW-A9300](https://scrapbox.io/brain-hackers/PW-A9300)」のページの「電源電圧検出」のリセット IC につながるピン（ENET0_RXD1・TX_EN・TXD0・TXD1 = GPIO4_4・4_6・4_7・4_8）と同じだとわかった（上の「WinCE の解析との関係」）
  - `userspace/power/battpins.c`: `HW_PINCTRL_DIN4` を `/dev/mem` から読むだけ（root、何も変えない）。`arm-linux-gnueabi-gcc -O2 -march=armv5te -static` でビルドして `/usr/local/bin/battpins` に置く。libgpiod のコマンドは Brainux に入っていない
  - `subpaneld` の電池の段: 見張りピン（`HW_PINCTRL_DIN4`）を 1 ms おきに 5 回読んだ多数決。GPIO4_8 が 0 → 空、GPIO4_7 が 0 → 1 段、GPIO4_4 が 0 → 2 段、それ以外 → 3 段（GPIO4_6 は使わない）。2 回続けて同じときだけ表示を変える
  - この段の決め方（どのピンが 0 なら何段か、GPIO4_6 を使わないこと）は、WinCE の `battdrvr.dll` の判定（アルカリ電池のとき）と同じ並び。逆アセンブルで知ったものを使った。使い切るまでの記録（上の「5V から取る電流」の 2 回目・3 回目の 1111 → 0011 → 0001 → 0000）とも合う

## 電池の電圧

- **電池の電圧は LRADC ch1 で読める**（brain-hackers の Scrapbox「PW-A9300」と、WinCE の解析による）。AUART0_CTS のパッド（GPIO3_2、どのドライバも使っていない）を 1 にすると FET が入り、電池が LRADC1 につながる。既定の scale では 4095 に張りつくので、ch1 を半分にして測る（`in_voltage1_scale` = 0.903320310）。ピンを 1 にしないで読むと raw 13（ほぼ 0）で、FET は効いている
  - WinCE の `battdrvr.dll` の逆アセンブル（2026-10-12）で、WinCE が GPIO3_2 を 1 にしてから LRADC ch1 を半分にして読むことは先に知っていた（そのときは電圧の読み方としては使わなかった）。Scrapbox で「LRADC1 が電池の電圧で、AUART0_CTS を H にすると FET が入る」と知り（2026-10-16）、実機で試した。`battvolt` の読み方の細部と分圧の比の見積もり（下）は、実機で試して決めた
  - `userspace/power/battvolt.c`: GPIO3_2 を 1 → 2 ms → `in_voltage1_raw` を 5 回読んで平均 → 0 に戻す（root、/dev/mem と iio）。ピンが GPIO の出力になっていなければ触らない。読む間はシグナルを止め、ピンが 1 のまま残らないようにする。同時に 2 本走ると、片方がピンを 0 に戻した瞬間にもう片方が読んで raw 43 になったので、`/run/battvolt.lock` で 1 本ずつにした。出力は `bvraw=3161 bv=2855`（bv は比を 1 とした mV）。2026-10-17 から brain-power.sh が呼び、brain-watch.log に 10 秒ごとに残る
  - 分圧の比はまだ決めていない。新品のアルカリ電池（2026-10-17、起動 29 分後、ハブの 5V あり、見張りピン 1111）で raw 3161（比 1 なら 2.855 V）が 10 分以上動かず、ハブを抜くとすぐ 2987 に下がった。動かなかった間は電池にほぼ負担がなかったと見ると、新品の開放の電圧（3.1〜3.2 V）から比は 1.1 前後。テスターがないので決めきれない。電池が減っていく間の読みと見張りピンの変わり目を並べて決める

## 動いている最中にハブ（5V）を抜き差しすると

- **動いている最中にハブ（5V）を抜き差しすると、挿し直したあとも電池から取り続けていた（直した、2026-10-17）**
  - 見つけたとき: 新品のアルカリ電池で、ハブありの間は raw 3161 で動かなかった。11:20:41 に抜くとすぐ 2987、11:21:23 に挿し直しても戻らず、5 分で 2820〜2860、15 分で 2715 まで下がった。5V の読みは挿し直す前の 4.97 V から 5.15 V に上がった（Brain が 5V から取る電流が減った）。レジスタは起動したときのまま（5VCTRL 0x24027111 = 上限 480 mA、DCDC4P2 0x10c01600）で、設定の上では 5V から取ることになっていた。前に「ハブがあっても電池は減る」と書いた件（上の 2 回目・3 回目）も、これだった見込みが高い
  - わけ: i.MX28 は 5V の抜き差しのたびに、ソフトで電源の経路を切り替える作り。Freescale の BSP（2.6.35 の `drivers/power/mxs/linux.c`・`ddi_power_battery.c`。GitHub に写しが多い。例: embeddedTS/linux-2.6.35.3-imx28）は、4P2 を使う設定（`VDD4P2_ENABLED`）のとき、抜けたら（`ddi_power_execute_5v_to_battery_handoff`）DCDC4P2 の ENABLE_DCDC・ENABLE_4P2 を落として PWD_CHARGE_4P2 を立て、挿さったら（`ddi_power_Enable4p2(450)`）4P2 を一から立ち上げ直す（DROPOUT_CTRL・TRG・CMPTRIP を整え、DC-DC を 4P2 から動かし直し、errata の偽の電圧低下が収まるまで待つ。`ddi_power_BringUp4p2Regulator` で上限を 0 にし、ENABLE_4P2、PWD_CHARGE_4P2 を落とし、4P2 の BO を 4150 mV に、CHARGE の ENABLE_LOAD を入れて上限を 100 mA ずつ 450 mA まで上げ、BO を 3600 mV に戻す）。linux-brain にはこの処理がない。抜けたときはハードが勝手に電池へ移るが、挿し直しても 4P2 は立ち上げ直されない
  - 起動のしかたで WinCE が残す値が違う: ハブありで起動すると DCDC4P2 0x10c01600（4P2 と、4P2 から動かす DC-DC が入。BO 4150 mV は立ち上げの途中の値のまま）・5VCTRL 0x24027111。電池だけで起動すると DCDC4P2 0x00000018（どちらも切）・5VCTRL 0x24300115（PWD_CHARGE_4P2 が 2 ビットとも立ち、ILIMIT_EQ_ZERO も立つ）。PWD_CHARGE_4P2 は i.MX28 では bit 20〜21 の 2 ビット（BSP の regs-power.h の 0x00300000）
  - 試したこと（`userspace/power/ramp4p2.c`）:
    - 上限を 0 → 100 mA ずつ 480 mA に上げ直すだけ: 変わらない
    - PWD_CHARGE_4P2 を 10 ms 立てて 4P2 を止め、上限 0 で起こし、上限を上げ直す（`pwd`。このときは bit 20 だけを触っていた）: ハブありで起動したあとなら戻った（5V の読み 5.15 V → 4.86〜5.01 V、電池 raw 2671 → 2796、60 秒で 2850）。電池だけで起動したあとでは戻らない（4P2 そのものが切られている）
    - ハブありで起動したときの値に持っていく（`full`）: 5VCTRL で上限 0・4P2 を止める → DCDC4P2 を 0x10c01600 から ENABLE_DCDC を抜いた値に（4P2 を入れる）→ 5VCTRL で PWD_CHARGE_4P2 の 2 ビットと ILIMIT_EQ_ZERO を落とし、上限を 100 mA ずつ 480 mA に → 10 ms 後に DCDC4P2 を 0x10c01600（DC-DC を 4P2 から）。電池だけで起動してハブを挿した状態で、5V の読み 5.06 V → 4.86 V、電池 raw 2665 → 2806 と戻った。ハブありで起動した状態から走らせても値は変わらず、5V から取ったまま
  - 自動にした: `brain-5v-ilimit` を常駐にした。起動時に上限を 480 mA に上げる（前と同じ）。そのあとキーボードのマイコンの「5V が挿さった」（brain-kbd-i2c の SW_DOCK）を待ち、来たら 1 秒待ってまだ挿さっているのを確かめ、`full` と同じことをする（見張りピンが 0000 なら飛ばす。4P2 を止める 20 数 ms は電池だけになるため）。起こし直す前の 1 秒と後の 2 秒で 5V の読みを平均し、80 mV 以上下がれば「drawing from 5V again」、下がらなければ「no sag: check battcheck」と journal に出す（前後の 5VCTRL・DCDC4P2 も）。続けて `brain-wifi-reprobe` を起こす（ハブを挿すと Wi-Fi の子機の初期化が -11 で失敗することがあり、そのときだけ子機の電源を切り直す）
  - 確かめ方: その場は `journalctl -u brain-5v-ilimit`。あとからは `sudo battcheck [分]`（`userspace/power/battcheck.py`。brain-watch.log の 5V がある間の bvraw の傾きを見て、-5/分より下がっていれば電池から取っている。悪いときは -30/分ほど、休んでいる電池は 0 以上）
  - 確かめたこと（2026-10-17）:

| 場面 | 常駐の記録（5V の読み） | battcheck |
|---|---|---|
| ハブありで起動 → 抜き差し（`pwd` の版） | 5150 → 4946 mV | +3.8/分 |
| 蓋で眠る → 眠ったまま挿す（`pwd` の版） | 5153 → 4948 mV | +2.3/分 |
| 同じ、2 回目（挿すと起き、蓋が閉じているので約 3 秒で眠り直した） | 5058 → 4806 mV | +3.1/分 |
| 電池だけで起動 → 挿す（`pwd` の版、bit 20 だけ） | 5067 → 5057 mV（no sag） | 下がり続けた（約 -12/分） |
| 同じ状態で `full` を手で | 5.06 → 4.86 V | 戻った |
| `full` の常駐で、ハブありの状態から抜き差し | 5064 → 4864 mV | +2.9/分 |

  - **眠っている間に 5V を挿すと起きる**（キーボードのマイコンの知らせが起こす。サブ液晶の様子から本人が確かめた）。蓋が閉じていれば logind が約 3 秒で眠り直させる
  - 残っている隙: 挿して起きたあと蓋が閉じたままだと約 3 秒で眠り直し、常駐の測る途中（挿してから約 5 秒かかる）で凍ることがある（結果は正しかった）。書き込みそのものは約 30 ms で、その途中で凍ると 4P2 を止めたまま眠る（起きれば残りが続く）。確率は小さいと見て、手当てはしていない。弱った電池（見張りピン 0001・0011 など）で 4P2 を止める間に落ちないかは、まだ試していない。挿したときに `brain-wifi-reprobe` を起こすのは動いた（14:25:42 に挿して起こし、子機の電源を 2 回切り直した）が、その時の切る時間（2 秒）では -11 が続いて戻らず、9 秒抜いて戻った。8 秒に延ばすと、同じ -11 から 1 回で戻った（15:00、[wifi-rtl8188eu.md](wifi-rtl8188eu.md)）

## 電源の状態を 1 行で出す

`userspace/power/brain-power.sh` が 1 行で出す（root でなければ pins は出ない）。`brain-watch.sh` も 10 秒ごとに同じものを記録する（`pwr=[...]`）。

```
src=5v batt=3412mV 5v=5002mV vddd=1559mV vddio=3216mV pins=1111
```

pins は GPIO4_4・4_6・4_7・4_8 の順。

## deep を作る（kernel/0009、2026-10-15、実機で level 0〜2 を確かめた）

`deep` を s2idle より深くする。手本は Freescale の 2.6.35 BSP の `mx28_cpu_standby`（`arch/arm/mach-mx28/sleep.S`、GPL）と、それを 3.10 の `mach-mxs` に移した Digi の版（`digidotcom/yocto-linux` の `arch/arm/mach-mxs/mx28-sleep.S`）。手元の写しは `~/brain-audio/ref/mx28-pm/`。

- `arch/arm/mach-mxs/suspend-mx28.S`（196 バイト）を起動時に OCRAM（物理 0x8000、`__arm_ioremap_exec` + `fncpy`）へ写し、`suspend_ops->enter` から呼ぶ。中でやること: CPU を 24 MHz の水晶へ（`CLKSEQ` の BYPASS_CPU）→ DRAM をセルフリフレッシュに（`HW_DRAM_CTL22` の LOWPOWER_CONTROL = 2、少し待つ）→ EMI のクロックと、CPU・EMI の分数分周器を止める →（level 2）PLL0 を止め、HBUS を 1/31 に → WFI → 逆の順に戻す
- MMU は入れたまま、レジスタは ioremap のアドレスで触る。最初に各レジスタのページを読んで TLB に載せ、セルフリフレッシュの間は DRAM に一切触れない（スタックもリテラルプールも使わない。逆アセンブルで再配置なしを確かめた）
- Freescale・Digi と違い、VDDD・VDDA・VDDIO は下げず、DC-DC の設定（MINPWR・LOOPCTRL）も触らない（NXP のフォーラムに「5V だけのときに電圧を下げると固まる」報告。まず動かすことを優先）。5V の電流上限（ILIMIT_EQ_ZERO）も触らない
- 眠っていた時間: RTC の秒のカウンタ（`HW_RTC_SECONDS`、読むだけ）を眠る前と起きたあとで読み、`.wake` で `timekeeping_inject_sleeptime64()` に渡す。RTC のドライバは使わない
- 深さは `/sys/module/mxs_pm/parameters/level`（起動時は `mxs_pm.level=`）: 0 = 前と同じ WFI だけ、1 = セルフリフレッシュとクロック止め、2（既定）= さらに PLL0 を止め HBUS を落とす。眠り方は 2026-10-15 から `deep`（`brain-sleep-mode.conf`。それまでは s2idle）
- メイン液晶（PW-A9300 の `brain-lq050j1ug01`）は画面を自分で覚えていて、LCDIF は書き換えのときだけ DRAM を読む。眠っている間はプロセスもコンソールも止まっているので、手当てしていない

試した順番（`userspace/power/deeptest.sh`。ハブ・Wi-Fi 子機をつないだまま。眠ったらキーで起こす）:

1. 0009 のカーネルで起動し、ふだんの s2idle（蓋・入/切）が前と変わらないこと
2. `deeptest.sh 0`: 前と同じ眠り方で、眠っていた時間が時計に足されること（RTC と時計の秒が揃う）
3. `deeptest.sh 1` → `deeptest.sh 2`: 眠って起きること、起きたあとキー・タッチ・音（イヤホン）・Wi-Fi・サブ液晶が動くこと
4. 動いたら、眠り方の既定を `deep` にするか決める。電池の減りを s2idle と比べる（見張りピン、一晩）

固まったら電池を抜く。`/boot` は空きが 6 MB ほどで zImage（7.1 MB）が 1 本入らないので、入れる前に古いものを 1 本 `~/boot-archive/` に移す（今回は `zImage.ymu818`）

結果（2026-10-15 夕方、#15。ハブ・Wi-Fi 子機つき、5V あり）:

| | 眠った時刻 → 起きた時刻（journal） | RTC で | 時計で | 起きたあと |
|---|---|---|---|---|
| s2idle（蓋） | 18:39:42 → 18:40:15 | | | 前と同じ |
| level 0 | 18:38:30 → 18:39:30 | 67 秒 | 67 秒 | Wi-Fi つながる（間に蓋の s2idle を挟んだので時間は測っていない） |
| level 1 | 18:42:08 → 18:43:31 | 89 秒 | 90 秒 | 画面・キー・タッチ（本人）、Wi-Fi 約 80 秒 |
| level 2 | 18:46:10 → 18:47:30 | 86 秒 | 86 秒 | 画面・キー・タッチ（本人）、両方のタッチの割り込み、Wi-Fi 約 80 秒、スピーカーで 440 Hz が鳴る（本人） |

- どれもキーを押すまで眠り、起きた時刻は本人が見た時刻と合う（level 0 は 18:39:32 ごろ、1 は 18:43:30 ごろ、2 は 18:47:30 ごろ）。時計は Chromebook とずれなかった
- Wi-Fi は 3 回とも、起きたときの probe が通った（`brain-wifi-reprobe` は出番なし）
- 既定を `deep` にしたあと（level 2）、蓋で 18:58:37 → 18:59:04（蓋を開けて起きた）、入/切で 18:59:14 → 18:59:49（キーで起きた）。どちらも `PM: suspend entry (deep)`、時計は Chromebook と合ったまま、Wi-Fi も戻った
- 電池だけ: 起きている間にハブを抜き（19:02:23）、蓋で 19:02:31 → 19:03:58（蓋を開けて起きた）。ハブは起きてから挿した（19:04:31）ので、眠っている間は 5V なし（brain-watch.log も前後とも `src=batt`）。起きたあと画面・キー・タッチが動き（本人）、時計は合ったまま、ハブを挿すと Wi-Fi も戻った
- 電池の減り（一晩）: 新しいアルカリ電池で、ハブを抜いて（22:19:59）蓋で 2026-10-15 22:20:08 → 10-16 08:23:57（10 時間 4 分、電池だけ）。見張りピンは眠る前 1111、起きた直後（ハブを挿したあと）も 1111、そのあと 5V ありで 1111 と 0111 を行き来。s2idle は 5 時間 34 分で 1111 → 0111 だったので、**deep のほうが眠っている間の減りがずっと小さい**（ピンが粗いので倍率は言えない）

## ツール（`userspace/power/`）

| ファイル | 用途 |
|---|---|
| `brain-power.sh` | 電源の状態を 1 行で出す（5V の有無、各電圧、電池の見張りピン、電池の電圧） |
| `brain-5v-ilimit.c`・`.service` | 起動時に 5V の電流上限を 480 mA に上げ、そのあと常駐して、5V が挿さったら（SW_DOCK）4P2 を起こし直し、brain-wifi-reprobe を起こす。前後の 5V の読みで効いたかを journal に出す。`/usr/local/bin/brain-5v-ilimit`、`/etc/systemd/system/` |
| `battcheck.py` | brain-watch.log から、5V があるのに電池の電圧が下がり続けていないかを判定する（`/usr/local/bin/battcheck [分]`、root） |
| `ramp4p2.c` | 4P2 の起こし直しを手で試す道具（実験用。今は brain-5v-ilimit がやる） |
| `battpins.c` | 電池の見張りピン（GPIO4_4/4_6/4_7/4_8）を読む |
| `battvolt.c` | 電池の電圧を LRADC ch1 で読む（GPIO3_2 を一瞬 1 にする） |
